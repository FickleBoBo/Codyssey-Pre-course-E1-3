# Codyssey Pre-course E1-3: AI가 계산하는 방식을 흉내 내는 작은 계산기 만들기

## 프로젝트 개요

컴퓨터가 십자가/X 같은 패턴을 구별하는 방식을 MAC(Multiply-Accumulate) 연산으로 직접 구현해본 미니 NPU 시뮬레이터입니다. 입력 패턴과 필터를 같은 위치끼리 곱한 뒤 모두 더해 유사도 점수를 계산하고, 점수가 더 높은 필터 쪽으로 패턴을 판정합니다.

- 모드 1: 3×3 필터 2개(A/B)와 패턴을 직접 입력받아 즉석 판정
- 모드 2: `data.json`의 필터·패턴을 일괄 로드해 PASS/FAIL 판정
- 크기별 MAC 연산 시간을 측정해 $O(N^2)$ 시간 복잡도를 실측 데이터로 확인
- [보너스] 임의 크기 Cross/X 패턴 자동 생성기, 2D→1D 배열 변환 기반 연산 최적화 비교

## 기능 목록

**모드 1 — 3×3 수동 입력**

- 필터 A/B 입력 (행/열 개수 불일치, 숫자 파싱 실패 시 안내 후 재입력 유도)
- 패턴 입력: 수동 입력 / `+`(Cross) 자동 생성 / `X` 자동 생성 중 선택 (잘못된 선택은 재입력 유도) — [보너스] 패턴 생성기 연동
- MAC 연산 후 A/B 점수 비교, 동점(epsilon 이내)이면 판정 불가 처리
- 연산 시간 측정(평균/10회) 출력

**모드 2 — `data.json` 분석**

- 필터 로드 시 라벨 정규화(`cross`/`+` → `Cross`, `x` → `X`)
- 최상위 스키마(`filters`/`patterns` 타입) 및 크기 불일치 검증 — 오류가 있어도 프로그램이 중단되지 않고 케이스 단위 FAIL 처리
- 패턴별 MAC 연산 → Cross/X 판정 → expected와 비교해 PASS/FAIL 출력
- 크기별(3×3~25×25) 평균 연산 시간·연산 횟수(N²) 성능 분석 — [보너스] 2D/1D 연산 시간 비교 포함
- 전체 테스트 수/통과/실패 요약 및 실패 케이스별 사유 출력

**공통**

- MAC(Multiply-Accumulate) 연산: 반복문 기반 직접 구현, 외부 라이브러리 미사용
- 점수 비교: 허용오차(epsilon = 1e-9) 기반 동점 판정

**보너스**

- 패턴 생성기(`pattern_generator.py`): 임의 크기 N에 대한 `Cross`/`X` 패턴 자동 생성, 모드 1 패턴 입력에 재활용
- 1D 최적화(`optimize_1d.py`): 2차원 배열을 1차원으로 변환해 MAC 연산 수행, 기존 2D 방식과 동일 입력·반복 횟수로 성능 비교

여기서 특이한 점이 VSCode로 실행할 때랑 python 명령어로 실행할 때랑 출력 결과가 약간 다른 것을 볼 수 있는데 VSCode로 실행한 쪽은 소수점 아래가 디테일하게 출력되고 python 명령어로 실행한 쪽은 깔끔한 것을 볼 수 있다.

VSCode 쪽 실행 결과 로그를 보면 힌트를 얻을 수 있었는데 파이썬 경로가 특이하게 잡혀있는 것을 볼 수 있다. 해당 경로의 파이썬은 3.9.6 버전이다. python 명령어로 실행한 경우는 3.14.6 버전으로 동작하는데 버전간 차이로 출력이 달라지는 것이 약간 특이했다.

나는 MAC 연산을 `sum` 함수를 활용해서 구현했는데 Python 3.12부터 `sum` 함수는 [Neumaier](https://docs.python.org/3/whatsnew/3.12.html) 보정 합산 알고리즘을 활용해 부동소수점 오차 교정도 상당히 된다고 한다. 두 버전이 마침 이 개선의 전과 후이기 때문에 이런 보정 차이가 출력 결과로 이어짐을 예상해볼 수 있었다.

```python
def mac(matrix1, matrix2):
    size = len(matrix1)
    return sum(matrix1[i][j] * matrix2[i][j] for i in range(size) for j in range(size))


def mac_test(matrix1, matrix2):
    total = 0.0
    size = len(matrix1)
    for i in range(size):
        for j in range(size):
            total += matrix1[i][j] * matrix2[i][j]

    return total
```

위와 같이 기존의 `mac` 함수와 같은 일을 하는 `mac_test` 함수를 만들어 줬다. `sum` 함수와 제네레이터가 하던 동작을 다시 2중 for문으로 풀어쓴 형태로 이제 `sum` 함수의 오차 보정을 받지 못하고 실수의 덧셈 반복에 의한 오차 누적이 쌓일 것으로 예상해볼 수 있었다. 이후 `mac_test` 함수로 변경 후 동일하게 프로그램을 실행하니 VSCode로 실행했던 것과 동일한 결과를 python 명령어로 실행했을 때도 얻을 수 있었다. 이런 보정으로 입실론 없이 정말 비교 연산자로도 판별하는 경우가 생길 수 있지만 보정이 부동소수점 오차를 근본적으로 없애주진 않기 때문에 안전하게 입실론 기반 판별을 하는 것이 여전히 좋아 보인다.

성능 표를 보면 2D 연산보다 1D 연산이 미세하게 더 빠른 것을 볼 수 있다. 2D든 1D든 행렬의 원소수는 $N^2$ 으로 동일하므로 mac의 시간 복잡도는 $O(N^2)$ 이 된다. 시간 측정의 경우 행렬 평탄화 등 잡다한 부분을 제외하고 순수 mac 연산만 측정해도 이런 차이가 발생했는데 이를 캐시 지역성이 원인일 것으로 예상했다. 배열의 경우 메모리 블록을 연속으로 차지하므로 CPU 캐시가 이 블록을 그대로 적재하면 캐시 적중률이 올라 데이터를 읽는데 걸리는 시간을 줄일 수 있지 않을까 했다. 하지만 이후 학습을 하며 파이썬의 경우 실수 값들도 객체로 다루기 때문에 이런 캐시 효과를 크게 못볼 수 있다는 점을 알게 됐다. 기본 타입의 경우 실제 값을 적재하는 일부 언어들과 달리 전부 참조 값으로 다루고 있어서 배열을 캐시에 올려도 실제 객체는 메모리에 여전히 있을 수 있다는 것으로 이해했고 따라서 이런 성능 차이는 오히려 참조 횟수를 한번 줄이는데서 기인할 수 있다는 것을 알게 됐다. 언어의 철학과 설계 원리에 대한 학습이 중요한 것을 배울 수 있었던 보너스 과제였다.
